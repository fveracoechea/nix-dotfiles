# Split nixpkgs Channels by Layer

This flake pulls from two nixpkgs channels. The **Release Channel** (`nixpkgs-stable`, the current `nixos-YY.MM` branch) builds the System layer on `nixos-desktop`: kernel, services, display manager, and the compositor. The **Latest Channel** (`nixpkgs`, `nixos-unstable`) builds the Home layer: apps, CLI, and tooling. Before this, one `nixos-unstable` input fed everything, so a `nix flake update` to get a newer coding agent also moved the kernel and forced a Hyprland source build.

The layer decides the channel, with one exception: a package that is version-coupled to something on the other side of the seam follows its partner instead of its layer. Today this covers the Hyprland satellites (`quickshell`, `hyprpaper`, `hyprshot`, `hyprpicker`, `hyprcursor`, `hypridle`, `hyprlock`), which live in the Home layer but track the compositor's IPC and protocol versions, so they come from the Release Channel. Without this exception they are the most likely breakage in the whole arrangement.

## Consequences

- `nixpkgs.pkgs` receives an already-built instance, and NixOS asserts that `nixpkgs.config` is empty in that case. So `allowUnfree` and `permittedInsecurePackages` live in `nixpkgsConfig` in `flake.nix`, shared by both instances, and hosts can no longer declare them.
- Home Manager runs on the Latest Channel through a plain `_module.args.pkgs` definition, which replaces the `mkDefault` that `useGlobalPkgs = true` supplies. The NixOS module tree still evaluates Home Manager with the Release Channel's `lib`, so `home.enableNixpkgsReleaseCheck` is off on `nixos-desktop`. Home Manager and `pkgs` do agree; only `lib` differs, and it supplies pure helpers. A Home Manager release that needs a newer `lib` function would break evaluation with a clear error.
- `macbook-pro` does not split. nix-darwin asserts that its own branch matches the Nixpkgs branch, so a Release Channel system layer there would need a second nix-darwin input plus the `nixpkgs-YY.MM-darwin` branch. Its apps come from Homebrew (ADR-0003), so the split would buy almost nothing. It still receives `pkgs-stable`, unforced, so the shared Home Manager modules keep one signature.
- `inputs.hyprland` and `inputs.musnix` follow `nixpkgs-stable`; every other input keeps following `nixpkgs`. `inputs.hyprland` still overrides Hyprland's own nixpkgs, so `hyprland.cachix.org` never matches and the compositor is source-built whenever the release branch moves. That is a few times a year instead of every update. Dropping the `follows` entirely would restore the cache at the cost of a third nixpkgs in the closure.
- Custom Packages choose their channel per entry in `packages/default.nix`, so consumers keep reading `dotfilesPkgs.<name>` and no call site knows which channel it got.
